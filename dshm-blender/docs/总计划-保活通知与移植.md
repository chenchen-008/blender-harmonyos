## 二、后台保活结论

### 1. 官方包怎么做的

bm dump 显示 com.suwan.blenderonharmonyos：

- backgroundModes = 256，即 TASK_KEEPING；
- 申请了 ohos.permission.KEEP_BACKGROUND_RUNNING；
- 申请了 ohos.permission.KEEP_BACKGROUND_RUNNING_SYSTEM；
- TASK_KEEPING 的 SDK 注释：background continuous calculate mode, for example 3D render。

所以通知不是普通提醒，而是长时任务的可见凭证。

### 2. 为什么删通知会停

长时任务申请成功后，系统会发一条关联通知。  
用户删除通知，等于用户主动取消长时任务，系统会停止/挂起应用。

这是华为的设计，不是 bug，也不能通过 API 隐藏通知继续保活。

### 3. 通知内容能不能分“正在渲染 / DSHM 调用”

**系统长时任务通知：不能自定义标题和正文。**

ContinuousTaskNotification 只有：

- slotType
- contentType
- notificationId
- continuousTaskId

没有 title / text 字段。  
系统文案由系统和应用名称生成，应用不能把它改成“正在渲染”或“DSHM 正在调用”。

**可以做的替代方案：**

1. 系统长时任务通知保持通用，例如“Blender 正在运行”；
2. 应用额外发一条普通通知，写清楚当前来源：
   - “Blender 正在本地渲染”
   - “DSHM 正在调用 Blender 计算”
3. 或者在 Blender 内 N 面板 / DSHM 对话里显示来源；
4. 只在真正计算时启动长时任务，用“通知出现/消失”区分是否在算。

注意：普通通知不是保活凭证；删系统长时任务通知仍然会停任务。

## 三、通知状态设计

应用内维护 compute_source：

- idle
- local_render
- external_dshm
- saving

启动长时任务的规则：

- 本地开始渲染/计算，且应用可能退后台：source=local_render；
- DSHM 通过 addon/TCP 发起计算：source=external_dshm；
- 任务结束或回到前台：stopBackgroundRunning；
- 用户删通知：收到 continuousTaskCancel，保存 checkpoint，标记 interrupted。

应用自有通知文案：

- local_render：
  - 标题：Blender 正在渲染
  - 正文：本地任务运行中，删除系统保活通知会停止
- external_dshm：
  - 标题：DSHM 正在调用 Blender
  - 正文：外部计算任务运行中，请保持 Blender 在后台
- idle / saving：
  - 取消自有通知，或显示“正在保存”

系统长时任务通知：保持官方通用文案，不尝试伪造/覆盖。

## 四、权限与配置

module.json5 需要：

- requestPermissions：
  - ohos.permission.KEEP_BACKGROUND_RUNNING（normal / system_grant）
  - ohos.permission.KEEP_BACKGROUND_RUNNING_SYSTEM（system_basic，普通测试签名可能拿不到）
- abilities：
  - backgroundModes: ["taskKeeping"]

注意：

- KEEP_BACKGROUND_RUNNING_SYSTEM 需要 ACL / 正式签名；
- API 24 还有 KEEP_BACKGROUND_RUNNING_SPECIAL_SCENARIO（2in1/tablet/phone），按设备与上架要求评估；
- 测试包如果拿不到 system_basic，可能只能在前台/分屏运行，不能稳定后台计算。

## 五、生命周期

1. 前台开始计算，申请长时任务；
2. 退后台，系统保持进程；
3. 用户删通知：
   - on('continuousTaskCancel') 触发；
   - 立即保存 .blend / checkpoint；
   - 停止渲染；
   - 标记 interrupted；
4. 回到前台：
   - 如果任务还在，恢复 UI 状态；
   - 如果已中断，提示用户。

可选：短时任务 requestSuspendDelay 只用于最后保存，不用于长计算。

## 六、和 DSHM 的衔接

DSHM 调用 Blender 时，需要让 Blender 侧知道“这是外部计算”：

1. addon 收到 DSHM 的 execute/render 请求；
2. addon 通过本地 IPC/文件标记把 source=external_dshm 写给 HAP；
3. HAP 更新自有通知；
4. 计算结束，恢复 idle。

如果没有这条链路，HAP 只能看到“Blender 在算”，无法区分来源。
