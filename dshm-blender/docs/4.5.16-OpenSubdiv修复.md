# 4.5.16 OpenSubdiv 修复记录

## 现象

4.5.16 编译报：

    fatal error: 'opensubdiv/osd/glPatchTable.h' file not found

根因：deps 的 OpenSubdiv 3.6.0 用 NO_OPENGL=ON 构建，没有安装 GL 相关头。

## 为什么不能只把开关改回 ON

缺头只是表象。Blender 4.5.16 的 intern/opensubdiv 里有 GPU 评估器代码，
但 OHOS 的图形后端是 Vulkan，桌面 GL 的 GPU 细分路径不可用。

## 实际修复

1. 从 OpenSubdiv 3.6.0 源码补：
   - glslPatchShaderSource.h

2. eval_output_gpu.h 的两个 GL 头只在非 OHOS 编译：

       #ifndef __OHOS__
       #include <opensubdiv/osd/glPatchTable.h>
       #include <opensubdiv/osd/glVertexBuffer.h>
       #endif

3. 增加 glsl_patch_shader_source_stub.cc，只提供 evaluator_capi 需要的：
   - GLSLPatchShaderSource::GetPatchBasisShaderSource()

4. 在 subdiv_modifier.cc 强制 CPU：

       static bool is_subdivision_evaluation_possible_on_gpu()
       {
       #ifdef __OHOS__
         return false;
       #endif
         ...

5. platform_ohos.cmake 改回：

       set(WITH_OPENSUBDIV ON ...)

## 能力边界

恢复：

- Subdivision Surface 修改器
- Multires / 多级细分
- CPU 细分

暂不提供：

- GPU subdivision（Vulkan 无桌面 GL compute 路径）
- OpenSubdiv 的 GL/GLSL GPU 评估器

## 验证

1. 打开 Blender，默认 Cube 加 Subdivision Surface；
2. 评估后的顶点/面数应增加；
3. Multires 可进入多级细分；
4. DSHM blender_run 读取 evaluated mesh 统计；
5. 4.5.16 HAP 启动无崩溃。

## 构建命令

    cd /opt/build/hm
    OHOS_SDK=/opt/ohos-sdk/linux OHOS_ABI=arm64-v8a JOBS=8       bash build.sh blender

## 备注
