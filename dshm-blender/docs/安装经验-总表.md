# 鸿蒙 Blender 安装经验总表

这份文档把散落在各处的踩坑记录集中起来，重点是可复现的安装/加载问题。

## 1. HAP 与包名

- 测试包名：com.suwax.blenderonharmonyos
- 原包：com.suwan.blenderonharmonyos，未修改
- 安装：hdc install -r entry-default-signed.hap
- HAP 约 395 MB；libblender.so strip 后约 93 MB
- 公开仓库的 build-profile.json5 已移除签名配置，构建前需在 DevEco 重新配置

## 2. namespace：最关键的一条

鸿蒙只允许从安装目录加载 .so：

- 允许：/data/storage/el1/bundle/libs/arm64/...
- 拒绝：/data/storage/el2/base/.../files/...

从 el2 加载会报：

    MUSL-LDSO ... check ns accessible failed

numpy 扩展必须放在 HAP 的 libs/arm64-v8a/numpy/**，不能只放在 python_home/site-packages。

另一个坑：OpenHarmony 的

    namespace.default.ignore_global_library=true

会让 RTLD_GLOBAL 加载的库对后续 dlopen 不可见。也就是说：

- dlsym(RTLD_DEFAULT) 能查到，不代表扩展能解析符号；
- 不能靠 RTLD_GLOBAL 让 numpy 扩展看到 Python 符号；
- 必须让扩展显式 NEEDED libpython3.11.so.1.0。

## 3. BIND_NOW 与 libpython

鸿蒙 musl 默认 BIND_NOW，dlopen 时所有符号必须立即解析。

numpy 扩展原来只有：

    NEEDED: libc.so

于是报：

    Error relocating ...: PyType_Ready: symbol not found

修法：

1. CPython 用 --enable-shared 重建，得到 libpython3.11.so.1.0
2. libblender 链接共享 libpython，确认 NEEDED 有 libpython3.11.so.1.0
3. numpy 的 LDSHARED 加 -L<python lib> -lpython3.11
4. 扩展 NEEDED 里必须有 libpython3.11.so.1.0
5. HAP 打包 libs/arm64-v8a/libpython3.11.so.1.0

不要只改 sys.setdlopenflags(os.RTLD_LAZY | os.RTLD_GLOBAL)，实测仍然失败：

    Error relocating libnp_lazy.so: PyLong_AsSsize_t: symbol not found

## 4. NEEDED 路径

交叉编译出来的 .so 可能带构建机绝对路径：

    /opt/build/hm/deps/.../libtbb.so

设备上不存在，加载失败。

处理原则：

- 不要反复用 patchelf，它会把 123 MB 的 libblender 撑到 522 MB；
- 原地改 ELF .dynstr，把绝对路径替换成 basename，文件长度不变；
- 相对路径 src/lib/Iex/libIex-3_2.so 也要改成 basename；
- soname 不一致（libpng / libpng16）时在 HAP 补兼容名。

相关工具：tools/analyze_deps.py、dshm-blender/docs/4.5.16-HAP打包.md

## 5. HAP 构建环境的坑

WSL 里直接跑 hvigor 会踩：

- Windows SDK 只有 cmake.exe / restool.exe，没有 Linux 可执行文件；
- 补 Linux 工具后又缺 API 23 头文件；
- 最终改用 Windows DevEco 自带 hvigorw 打包最稳。

Windows 构建环境：

    DEVECO_SDK_HOME = D:/Huawei/DevEco Studio/sdk
    NODE_HOME = D:/Huawei/DevEco Studio/tools/node
    JAVA_HOME = D:/Huawei/DevEco Studio/jbr

产物：

    entry/build/default/outputs/default/entry-default-signed.hap

## 6. Addon 与 DSHM 安装

Blender addon 路径：

    /storage/Users/currentUser/Download/<bundle>/.config/blender/4.5/scripts/startup/dshm_bridge.py

addons 副本：

    .../scripts/addons/dshm_bridge/__init__.py

桥端口：9876。设备侧用 hdc fport 映射到本机。

DSHM 插件安装后，升级 HAP 或 DSHM 核心可能需要重装插件；插件本身无 child_process。

## 7. Native 子进程（headless worker）

已验证：

- 官方 OH_Ability_StartNativeChildProcess 可用；
- 子进程加载 libblender_worker.so:Main；
- Main 必须 extern "C"，否则 C++ 会 mangle 成 _Z4Main...；
- 子进程里 dlopen("libblender.so") + Blender_Init(--background) 可跑 bpy；
- 子进程没有 UI/Context，Main 返回后进程退出；
- 常驻版用 Unix socket 复用，socket 在应用沙箱 files 目录。

验证结果：

    VER 4.5.16 LTS NUMPY 1.24.4 SUB 98 96

## 8. 常见报错对照

| 现象 | 原因 | 修法 |
|---|---|---|
| MUSL-LDSO check ns accessible failed | .so 放在 el2 | 移到 el1 bundle libs |
| PyType_Ready: symbol not found | 扩展没有 NEEDED libpython | 重编扩展，显式链接 libpython |
| dlsym 能查到但扩展失败 | ignore_global_library=true | 不要依赖 RTLD_GLOBAL，改 NEEDED |
| dlopen failed | 路径/namespace 不对 | 用 HAP libs，检查 NEEDED basename |
| HAP 827 MB | patchelf 把 .so 撑大 | 原地改 .dynstr，不要 patchelf |
| EEVEE 全黑 | Maleoon 910 Vulkan 限制 | 用 Workbench / Cycles CPU |
| 换包名后字体/目录错 | 公共路径硬编码 | setPublicHome 传真实 bundle 路径 |
