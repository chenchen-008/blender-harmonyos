# dshm-blender 剩余能力移植评估

> 目标：把 dsh-blender-plugin v2.6.1 的能力面移植到 DSHM 端侧（dshm-blender）。
> 现状：dshm-blender 0.1.0，19 个工具，plan catalog **28 family / 186 op**。
> 上游：dsh-blender-plugin v2.6.1，15 个工具，**33 family / 217 op**。

## 一、catalog 差异（已实测）

dshm 已有 family 全部是上游的子集，没有多出来的 family。

缺少 5 个 family：

- assembly
- blockout
- eval
- visualreport
- shapesolve

缺少 2 组 op：

- img：digest、probe、measure、calib
- gate：preflight、checkpoint、deliver

合计 **5 family + 31 op**。

## 二、这些能力依赖什么

| 能力 | 主要依赖 | 端侧可移植性 |
|---|---|---|
| img_* | bpy + numpy + bpy.image | 等 numpy 可用后可移植 |
| gate_* | 文件/状态 + bpy | 可移植，无 spawn |
| assembly / asm_* | bpy 几何 + 清单 JSON | 可移植，无 spawn |
| blockout_* | bpy 几何 + 渲染 + numpy 拼图 | 大部分可移植；转台 MP4 需要编码器，端侧受限 |
| eval_run | bpy + numpy | 等 numpy 可用后可移植 |
| visualreport_report | bpy + numpy（无 PIL） | 等 numpy 可用后可移植 |
| shapesolve_solve | bpy + numpy 光栅化 | 等 numpy 可用后可移植 |
| headless / worker / job | 新起 Blender 进程 | **不可移植**（DSHM 端侧无 spawn） |

结论：**除 headless/worker 外，其余 5 个 family 主要是“把 runtime Python 模块搬进 addon + 加 dispatch + 补 catalog”**，不是重写算法。

## 三、当前架构

- DSHM 侧：lib/index.js 注册工具；blender_plan 通过 addon 的 plan 命令转发。
- Blender 侧：addon/dshm_bridge.py 单文件，COMMANDS 目前 31 条。
- 上游：runtime/*.py 是算法模块，engine.mjs 负责调度；不能直接整包塞进 DSHM。

移植方式：

1. 把上游 runtime 里对应模块复制到 dshm-blender/addon/runtime/；
2. 在 addon 增加 plan 入口，按 op 前缀 dispatch；
3. 在 lib/plan-catalog.js 增加 5 family 和 7 个 img/gate op；
4. 在 lib/index.js 的 blender_plan 执行路径接上；
5. 每个 family 加 selftest/help。

## 四、分阶段建议

### P1：img + gate（最先）
- img_digest / probe / measure / calib
- gate_preflight / checkpoint / deliver
- 理由：纯 bpy/numpy，不涉及新进程；能补齐 7 个 op。

### P2：assembly
- asm_scan / manifest / merge / repair / export / gate
- 理由：几何与清单，和现有 audit/fix 接近。

### P3：blockout + eval
- blockout_base / batch / export / turntable / refsheet
- eval_run
- 注意：turntable 需要视频编码，端侧先降级为 PNG 序列。

### P4：visualreport + shapesolve
- visualreport_report
- shapesolve_solve
- 前提：设备 HAP 必须已经带 numpy（4.5.16 C 方案）。

### P5：catalog/文档收口
- 目标 33/217
- 更新 README、AGENTS、工具数量、验收判据
- 加 npm test 回归

## 五、阻塞项

1. **设备 numpy**：当前 4.5.12 HAP 没有 numpy；P1 的 img/gate 可以先做，P3/P4 要等 4.5.16 HAP。
2. **spawn 限制**：headless/worker 不能移植；不要承诺。
3. **视频编码**：blockout turntable 先输出 PNG 序列，MP4 作为可选。
4. **上游 runtime 体积大**：assembly.py 229 KB、blockout.py 116 KB、imgtools.py 121 KB，不能整包复制，按 op 裁剪依赖。

## 六、验收

- blender_plan(op="catalog") 返回 33 family / 217 op；
- 每个新增 op 有 selftest；
- 真机：img_measure、asm_scan、gate_preflight 至少各跑通一次；
- numpy 可用后：visualreport_report、shapesolve_solve 跑通；
- 不新增 spawn 路径。
