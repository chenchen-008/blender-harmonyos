# dshm-blender 代码审计：同类路径/沙箱问题

> 范围：dshm-blender 0.1.0（lib/index.js、lib/protocol.js、addon/dshm_bridge.py、README/docs）
> 背景：新 bundle 测试时发现“字体变小”，根因是 HAP 壳改了 bundleName，但原生 libblender.so 仍写死旧 bundle，导致 userpref 读不到。这里检查 dshm-blender 是否有同类问题。

## 结论

- **代码里没有写死 com.suwan / com.chenchen008 / 具体 bundle 名**，这点是干净的。
- **但存在同类“HOME/公开目录不一致”风险**：addon 用 os.path.expanduser("~")，HAP 用 PUBLIC_HOME 常量；两者一旦不一致，保活标记、preset、txn 会静默分叉。
- **没有发现 numpy 顶层 import**；glTF 只在导出时捕获错误。这点 OK。
- **没有 child_process / 原生模块 / WASM**，符合 DSHM 约束。

## 正向确认

- lib/index.js / protocol.js 没有写死 bundle 或 /storage 路径。
- addon 没有顶层 import numpy；只有 glTF 导出异常时判断。
- 没有 child_process / WASM / 原生模块。
- TCP 通道、token、超时、错误映射结构清晰。
- txn/preset 默认放在 ~/.dshm-blender，逻辑本身合理，问题只在 HOME 解析。

## 建议修复顺序

1. A12 构建期 bundle 一致性检查（防止再次出现字体/userpref 问题）；
2. A1/A2 统一 HOME/公开目录解析，并打日志；
3. A3 saveWorkspace 不再静默回退 tmp；
4. A4/A5 临时文件唯一化 + 无 GUI 明确报错；
5. A6/A7/A8 文案与 loop 行为；
6. A9/A10/A11 文档与能力协商。

## 构建期检查建议

在 HAP 构建前跑：

    app_bundle = app.json5.bundleName
    public_home_suffix = EntryAbility.ets PUBLIC_HOME 的最后一段
    native = libblender.so 中 "com.*.blenderonharmonyos" 字符串
    assert app_bundle == public_home_suffix == native

本次就是这三处不一致：app.json5/EntryAbility 改成了新 bundle，libblender.so 仍是 com.suwan。
