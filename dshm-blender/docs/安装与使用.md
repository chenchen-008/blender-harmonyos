# 安装与使用

本文覆盖两条安装路径：GitHub bundle 安装（推荐）与设备内安装（离线/开发）。

## 0. 前置

- 鸿蒙设备上已安装 DSHM（com.dshm.dshclient）与 Blender 鸿蒙移植版
  （本次验收为 com.suwan.blenderonharmonyos 4.5.12）。
- Blender 必须能打开 Python Console 并安装 addon。
- 同机使用需要分屏（见第 4 节）。

## 1. 安装 Blender 侧 addon

### 方式 A：偏好设置安装

1. 打开 Blender → Edit → Preferences → Add-ons。
2. 右上角 Install，选择 addon/dshm_bridge.py。
3. 搜索 DSHM，勾选 **DSHM Blender Bridge**。
4. 3D 视图按 N，侧栏出现 DSHM 标签；确认 Status: listening。

### 方式 B：Python Console 安装（无文件选择器时）

1. 把 addon/dshm_bridge.py 放到 Blender 能访问的位置。
2. 打开 Python Console，执行：

~~~python
import bpy, os
src = "/path/to/dshm_bridge.py"
dst = os.path.join(bpy.utils.user_resource("SCRIPTS", path="addons", create=True), "dshm_bridge")
os.makedirs(dst, exist_ok=True)
open(os.path.join(dst, "__init__.py"), "wb").write(open(src, "rb").read())
bpy.ops.preferences.addon_enable(module="dshm_bridge")
bpy.ops.wm.save_userpref()
~~~

### 验证

在 DSHM 里调用 blender_status。Blender 在前台/可见时应返回 kind=ok。
也可以从 PC 用 hdc fport 后手工 ping：

~~~text
{"type":"ping","params":{}} + 换行
→ {"status":"success","result":{"pong":true,"blender":"4.5.12 LTS",...}}
~~~

## 2. 安装 DSHM 侧插件

### 方式 A：GitHub bundle（推荐）

1. 把仓库 push 到 GitHub。仓库根目录必须直接有 package.json、lib/index.js。
2. DSHM → 插件 → 安装，填仓库地址。
3. 重启 DSHM（force-stop + 重新打开即可，不要卸载）。
4. 新会话里调用 blender_status。

说明：包声明了 dsh.bundle.patch，插件管理器会把它作为 profile bundle 挂载，
并自动应用 cordis.patch.yml 里的 insert 行。不要同时在用户 patch 里再写一行，
否则同名工具会重复注册。

### 方式 B：设备内安装（本次验收使用）

适用：没有 GitHub 发布权限，或需要离线安装。

1. PC 上启动 HTTP 服务，把仓库根目录暴露在 8002：

~~~bash
python -m http.server 8002 --bind 127.0.0.1
~~~

2. 连接设备并做反向端口转发：

~~~bash
hdc rport tcp:8002 tcp:8002
~~~

3. 在 DSHM 会话里让 agent 用 python 工具执行 tools/install_on_device.py
   （或直接把脚本内容贴进 python 工具）：

~~~text
用 python 下载并执行 http://127.0.0.1:8002/tools/install_on_device.py
~~~

4. 脚本会：
   - 找到 DSH_HOME（home/profiles 与 cores 可能是兄弟目录）；
   - 定位当前核心版本；
   - 写入核心树与 profile 的 node_modules/@dsh-external/dshm-blender；
   - 把包加入 @deepseek-ai/dsh-web-app 的 dependencies（Loader 的依赖闭包），
     并保留一份 package.json.bak-dshm-blender；
   - 在 $DSH_HOME/cordis.patch.yml 追加 insert 行；
   - 打印 INSTALL_OK、core、patch、文件数与总字节数。

5. 重启 DSHM（只杀进程，不卸载）：

~~~bash
hdc shell aa force-stop com.dshm.dshclient
hdc shell aa start -a EntryAbility -b com.dshm.dshclient
~~~

6. 验证工具注册：调用 blender_status。若仍不存在，看 node-output.log 里的
   dshm-blender 行；常见错误是 schema 非法或依赖闭包未包含该包。

## 3. 工具用法

### blender_status

先调它。kind=ok 才继续；kind=error 会写明原因。

### blender_scene / blender_object

~~~json
{"limit": 100}
{"name": "Cube"}
~~~

### blender_run

~~~json
{"code": "bpy.data.objects['Cube'].rotation_euler.z += 0.5", "see": true}
~~~

返回 executed、stdout/stderr/traceback、毫秒数，以及一帧视口图。
持久内核 K 跨调用保留：

~~~python
K.n = getattr(K, "n", 0) + 1
~~~

### blender_see

~~~json
{"max_size": 640}
~~~

### blender_export

~~~json
{"format": "obj", "inline": true}
~~~

inline=true 会把字节写回会话工作区，并返回 DSHM 路径。
glb/gltf 在这台设备上因缺 numpy 不可用，会明确报错。

## 4. 分屏（同机必须）

1. 从底部上滑并停住，进入最近任务。
2. 把 Blender 与 DSHM 放入分屏，或让 DSHM 悬浮在 Blender 上。
3. 确认 Blender 画面还在刷新。
4. 再调用 blender_status。

后台冻结的判据：TCP connect 成功、发送成功、recv 超时 0 字节。
插件会把这种情况翻成「请分屏」的提示，而不是裸超时。

## 5. 配置

文件：$DSH_HOME/dshm-blender.json

~~~json
{
  "host": "127.0.0.1",
  "port": 9876,
  "token": "",
  "timeoutMs": 30000,
  "imageTimeoutMs": 90000
}
~~~

环境变量优先级最高。局域网连接时 addon 侧 host 改 0.0.0.0 并设置 token，
DSHM 侧 host 填 PC 的局域网 IP、token 同值。

## 6. 故障排查

| 现象 | 原因 | 处置 |
|---|---|---|
| kind=error，ECONNREFUSED | Blender 没运行 / addon 没启用 | 启动 Blender，启用 DSHM Blender Bridge |
| kind=error，连接成功但 0 字节 | Blender 在后台被冻结 | 分屏/悬浮，保持可见 |
| 工具不存在 | 插件没激活 | 看 node-output.log 的 dshm-blender 行 |
| JsonSchemaError additionalProperties | 工具参数 schema 非法 | 升级到 0.1.0 修复版 |
| glTF/GLB 报 numpy | 鸿蒙 Blender 未带 numpy | 改用 obj/stl/ply |
| 导出 Permission denied | 路径不在 Blender 沙箱 | 用默认临时目录或 ~ 下路径 |

## 7. 卸载 / 回滚

设备内安装：

1. 删 $DSH_HOME/cordis.patch.yml 里的 dshm-blender insert 行；
2. 删核心树与 profile 的 node_modules/@dsh-external/dshm-blender；
3. 用 package.json.bak-dshm-blender 还原 dsh-web-app/package.json；
4. 重启 DSHM。

GitHub 安装：在插件页停用/卸载该 bundle，重启。

Blender addon：偏好设置里取消勾选并 Remove；或删
scripts/addons/dshm_bridge 目录。

## 8. 安全

- addon 默认只监听 127.0.0.1，不暴露到局域网。
- 非回环监听必须设置 token，否则拒绝启动。
- 通道可以执行任意 Python；只在你信任的设备和网络里使用。
- 不要把 token 提交到仓库或贴进公开日志。
