# Blender 4.5.16 HAP 打包记录（Windows）

## 结论

4.5.16 + OpenSubdiv HAP 已在 Windows 上用 DevEco 自带 hvigorw 打包成功，并安装到测试包 `com.suwax.blenderonharmonyos`。

## 关键命令

```powershell
$env:DEVECO_SDK_HOME = 'D:\Huawei\DevEco Studio\sdk'
$env:NODE_HOME = 'D:\Huawei\DevEco Studio\tools\node'
$env:JAVA_HOME = 'D:\Huawei\DevEco Studio\jbr'
$env:PATH = "$env:JAVA_HOME\bin;$env:NODE_HOME;$env:PATH"

cd D:\dsh_plugin\blender-harmonyos-app
& 'D:\Huawei\DevEco Studio\tools\hvigor\bin\hvigorw.bat' assembleHap --no-daemon --mode module -p product=default
```

## 为什么不在 WSL 打包

WSL 里 hvigor 调用的是 Windows SDK 的 native 工具，只有 `cmake.exe` / `restool.exe`，没有 Linux 可执行文件；强行补 Linux 工具后又会缺 API 23 头文件。

结论：**原生 HAP 直接走 Windows DevEco 工具链最稳**。

## 依赖修补

`libblender.so` 的 DT_NEEDED 带有构建机绝对路径（如 `/opt/build/hm/deps/.../libz.so`），设备上不存在。

处理方式：原地把绝对路径字符串替换为 basename（保持 ELF 长度不变），避免 `patchelf` 把 123 MB 的 .so 撑到 522 MB。

结果：

- `libblender.so`：约 93 MB（strip 后）
- HAP：约 395 MB
